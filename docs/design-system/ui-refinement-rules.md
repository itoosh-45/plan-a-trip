# כללי עיצוב לסבב החידוד

תאריך: 2026-09-29  
קשור ל־[תוכנית העבודה](../ui-ux-refinement-plan.md)

## הכיוון

הגרסה הקיימת היא נקודת המוצא. משאירים את המשטחים הלבנים, הרקע הבהיר, Noto Sans Hebrew, הטורקיז והוורוד, כרטיסים שטוחים ואייקונים עדינים. החידוד מגיע מקריאות, סדר וריווח. לא מוסיפים גרדיאנטים, גבולות כהים, צללים כבדים או כרטיס נפרד לכל משימה.

## צבע וניגודיות לפי תפקיד

| תפקיד | כלל |
| --- | --- |
| רקע ומשטח | להשתמש ב־`--color-bg` וב־`--color-surface` הקיימים; מסך האשף בעיקר לבן, הקבוצות בלבן על רקע אפור בהיר |
| טקסט ראשי | `--color-text` הקיים לכותרות, שמות משימות, ערכים וכפתורים |
| הסבר שנדרש כדי להבין פעולה | `--color-text-dim` (כיום `#4A5461`) ולא `--color-text-mute`; לשמור על קריאות גם במסך אייפון |
| מטא־דאטה בלבד | `--color-text-mute` עבור מונים, תאריכים משניים ופרטים שאינם תנאי לפעולה |
| פעולה ראשית | `--color-highlight` הוורוד הקיים, פעולה ראשית אחת בכל אזור |
| פעולה קלה / חיווי | `--color-accent` הקיים במינון קטן; אין צורך למלא בו אזורים גדולים |
| הפרדה | `--color-hairline` או מרווח; גבול כהה אינו דרך להדגיש כרטיס |

הבעיה בדוגמאות הראשונות הייתה שהסברי השדות וסימוני הרשות קיבלו צבע ומשקל של מטא־דאטה. כל טקסט שמשפיע על ההחלטה של המשתמש חייב להיות קריא מקריאה רגילה, גם כשהוא משני.

## סולם טיפוגרפי לאשף ולרשימות

- כותרת שלב באשף: 20px, משקל 600, גובה שורה כ־1.35.
- משפט פתיחה של שלב: 14px, משקל 500, `--color-text-dim`, גובה שורה כ־1.55.
- תווית שדה: 14px, משקל 600, צבע טקסט ראשי.
- ערך בשדה: 16px לפחות, כדי לשמור על קריאות ולמנוע zoom אוטומטי ב־iOS.
- הסבר תחת שדה: 13px, משקל 500, `--color-text-dim`, גובה שורה כ־1.45.
- תווית ״חובה״ או ״אפשר אחר כך״: 12px לפחות, משקל 600. ״חובה״ בוורוד; ״אפשר אחר כך״ בטקסט משני קריא.
- שם משימה או פריט ברשימה: 16px, משקל 500, וגלישת שורה טבעית במקום קיטום מוקדם.
- קטגוריה או כותרת קבוצת משימות: 15–16px, משקל 600.
- סטטוס/פרט משני ברשימה: 13px; מונה או תאריך שאינם חיוניים יכולים להיות 12px.
- לא להשתמש ב־11px להסבר, הוראה, תווית פעולה או סטטוס שחייבים להבין. 11px נשאר רק במקומות זניחים אחרי בדיקת קריאות במכשיר.
- לשמור על משקלי 400/500/600 שמוגדרים בשפה הקיימת; לא להכניס bold גורף.

## קומפוזיציה

- אשף: כותרת ושורת הסבר קצרה בראש כל שלב; הסבר הפיצ'ר ליד השדה שאליו הוא שייך, לא מסך ארוך שמפרט את כל האפליקציה.
- סימון רשות/חובה מפורש בכל שלב. שלב אופציונלי ניתן לדילוג, ושדות החובה בתוכו מסומנים כחובה מותנית רק אם המשתמש מוסיף יעד.
- כפתור פעולה ראשית ברור ונמוך במסך; פעולת דילוג משנית ואינה מתחרה בו.
- רשימה: לשמור על שלב → קטגוריה → משימה, על השורה הלבנה ועל האייקונים השקטים. להגדיל את הטקסט ואת המרווח האנכי לפני הוספת צבע או מסגרות.
- אזורי מגע 44px לפחות, שדות 16px, RTL תקין ורוחב 320–430px בלי גלילה אופקית.
- בדיקה חזותית על מסך אייפון אמיתי או תצוגה אמינה היא חלק מקריטריון הסיום; צילום desktop מוקטן אינו מספיק.

## קופי בארבעת שלבי יצירת טיול

1. פרטי הטיול: שם חובה; תאריכים אופציונליים ובונים לוח ימים; מטבע ראשי עם ברירת מחדל ומשמש לתקציב ולסיכום.
2. יעדים: שלב אופציונלי; אם מוסיפים יעד, שם וטווח תאריכים חובה. להסביר שפריטים והוצאות יופיעו לפי יעד.
3. תקציב: שלב אופציונלי; תקרה לכל הטיול והקצאות לפי יעד. אפשר לעבוד בלי תקציב ולחזור אליו. המרת מטבע מוצגת רק כשיש שער שמור; כשאין, מסבירים מה לעשות בלי להציג שגיאה מפתיעה לאחר שמירה.
4. רשימת הכנה: שלב אופציונלי; בחירת משימות מקטלוג או הוספה עצמית, סימון ביצוע בהמשך. יש דרך ברורה לסיים בלי למלא את הרשימה.

## כללי קבלה

- משתמש חדש יכול לומר בכל שלב מה חובה, למה השדה משמש ומה יוכל להשלים אחר כך.
- הסברים ותוויות רשות קריאים על לבן בלי להגדיל את כל הממשק או להכהות את הרקע.
- המראה נשאר מזוהה עם האפליקציה המקורית; העיצוב החדש אינו מגדיר פלטה או שפת רכיבים חדשה.
